# 源码导读

启动器分为 Vue 界面和 Tauri 后端。界面通过命令请求数据、提交操作，并订阅进度和日志事件；文件、账户、下载和游戏进程由 Rust 处理。

## 前端从这里开始

`src/main.js` 挂载 Vue，`src/App.vue` 负责主窗口与页面布局。`src/useApp.js` 保存主界面的目录、版本、Java、内存和运行状态。`src/useLauncher.js` 集中封装 Tauri 命令与事件。

| 文件 | 内容 |
| --- | --- |
| `src/AccountDialog.vue` | 离线账户和微软登录界面 |
| `src/DownloadCenter.vue` | 平台切换、内容筛选、项目介绍和安装确认 |
| `src/GameDownloads.vue` | Minecraft 版本和实例安装页面 |
| `src/composables/useGameDownloads.js` | 游戏目录、加载器、安装计划和任务状态 |
| `src/VersionSelect.vue` | 可搜索的本地版本选择器 |
| `src/contentFormat.js` | 项目介绍处理、链接校验和兼容性判断 |

页面样式分别放在 `src/styles.css`、`downloads.css`、`game-downloads.css`、`account.css` 和 `library.css`。

## Rust 后端

| 文件 | 内容 |
| --- | --- |
| `src-tauri/src/main.rs` | Tauri 命令、窗口、系统对话框和事件转发 |
| `src-tauri/src/core.rs` | 设置、版本解析、Java 选择和游戏进程 |
| `src-tauri/src/auth.rs` | 微软设备授权、Xbox/Minecraft 认证与凭据存储 |
| `src-tauri/src/modrinth.rs` | Modrinth 内容查询、依赖和文件安装 |
| `src-tauri/src/curseforge.rs` | CurseForge API 适配和本地 Key 管理 |
| `src-tauri/src/install.rs` | Minecraft、加载器和整合包安装 |
| `src-tauri/src/net.rs` | 网络主机校验、下载、重定向和完整性校验 |

`src-tauri/src/bin/core-probe.rs` 是开发用测试入口，不会打入便携版。Rust 测试分布在 `tests.rs`、`auth_tests.rs`、`modrinth_tests.rs` 和各模块的测试代码中。

OptiFine 的无界面安装入口在 `src-tauri/helpers/XumobOptiFineInstall.java`。修改后需要用 Java 8 兼容目标重新编译对应的 `.class`。

## 下载与安装调用顺序

内容下载依次搜索项目、读取介绍和版本、预览安装计划，然后才由用户确认并提交文件。Modrinth 与 CurseForge 共用安装流程，平台适配层负责转换各自的接口响应。

游戏安装由 `src/composables/useGameDownloads.js` 发起：

1. `game_catalog` 读取 Minecraft 版本列表。
2. `game_components` 查询所选版本可用的加载器和组件。
3. `game_prepare` 校验配置并生成预览。
4. `game_install` 安装并提交独立实例。
5. `game_cancel` 取消当前任务。

修改这条流程时，留意目录和实例名称校验、已有文件保护、取消清理，以及切换版本后忽略过期组件响应。
