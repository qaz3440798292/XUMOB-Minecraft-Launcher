# XUMOB Minecraft Launcher v0.5.0 · 微软正版登录

## 使用

1. 解压新版便携包，运行 `XUMOB Minecraft Launcher.exe`。
2. 点击右上角账户或首页启动面板的“修改”。
3. 选择“微软正版”→“登录微软账户”。
4. 复制短代码，点击“打开微软登录页”，在系统浏览器中的微软页面完成登录并输入代码。
5. 授权完成后，窗口自动显示 Minecraft Java 版角色，启动时使用该角色的正版身份。

已配置本次提供的 Client ID `530c101a-f756-496e-8099-6addb6ed06ed`，只有应用获得 Minecraft 服务许可后才能完成正版登录；成功获取微软授权代码不能证明已获许可。微软授权页面的应用名称由该 ID 的注册信息决定。账户窗口折叠的“登录应用配置”可修改 ID，无需 Client Secret。

保留离线账户。切换回离线不会移除已保存的正版登录；“退出登录”会移除本启动器的登录凭据并恢复离线模式。游戏运行或准备期间不能更换账户。

旧版 data 文件夹可迁移到新版旁，原有多目录、独立设置和离线用户名保持兼容。新版不预先保存你的微软账户，需要你完成一次授权。

## 已实现

微软设备授权 → Xbox Live → XSTS → Minecraft 访问凭据 → Java 版授权与角色检查。角色名、UUID、访问令牌、XUID 和客户端标识从认证链读取；正版身份与离线 UUID 分开使用。

启动时检查授权与当前角色，登录过期时自动刷新。认证失效、订阅失效、缺少角色、家庭设置限制、拒绝授权、代码过期或网络异常均有提示，正版模式不会静默降级为离线账户。

使用系统浏览器登录，软件不读取或保存密码。刷新令牌和 Minecraft 凭据由当前 Windows 用户的 DPAPI 加密保存在 `data/account-session.bin`，公开角色资料和账户类型在 `data/account.json`。换电脑或 Windows 用户后重新登录。

凭据不返回给界面，日志会隐藏令牌，长参数文件只保存非敏感内容；Java 进程按标准游戏启动方式从进程参数接收访问令牌。退出本启动器账户不会退出浏览器中的其他微软会话。

## 验证范围

- **真实微软接口**：提供的 Client ID 成功申请设备授权代码；返回有效微软授权网址、轮询间隔和期限。检测结束后已取消本地会话，没有代替用户登录个人账户。
- **34 项 Rust 测试全部通过**：保留原核心回归，并覆盖完整认证链的模拟响应、授权检查、刷新轮换、取消时的并发响应、加密保存与恢复、损坏缓存、注销、身份一致性和令牌隔离，以及退出后的延迟日志脱敏。
- **实际 Java 22**：验证中文参数、路径、访问令牌和长参数文件顺序。Java 在主类之后不再展开后续参数文件，因此正版启动把令牌及其后续游戏参数直接传入，避免丢失参数。
- **账户界面**：默认 Client ID、代码与浏览器入口、登录完成状态、失败提示、取消、注销与离线切换通过模拟场景回归；无界面脚本错误。
- **原有功能**：多目录、版本独立设置、环境检查、Java 进程与中文日志、模组搜索、依赖修复、停止/关闭确认和窗口操作继续通过。

尚未使用你的个人账户完成真实 Xbox/Minecraft 授权，也未验证正版服务器连接。完整真人登录需要你在微软页面完成授权；界面示意截图中的示例角色不是你的真实登录状态。

协议参考：[微软设备授权说明](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)、[Minecraft/Xbox 认证实现参考](https://github.com/Voxelum/minecraft-launcher-core-node/blob/master/packages/user/microsoft.ts)。

## v0.5.0 登录拒绝修正

旧版将 Minecraft 登录 HTTP 403 一律解释为应用许可问题。新版仅在明确返回 Invalid app registration 时给出该判断，其他拒绝显示未知或非 JSON 分类。诊断文字可选中复制，不暴露原始响应和令牌。详细操作见 [403 排查说明](Minecraft登录403排查说明.md)。


v0.5.0 新增 Modrinth 模组、资源包与光影下载中心。微软授权页面的应用名称仍由注册的 Client ID 决定，修改启动器名称不会改变微软后台应用注册信息。
