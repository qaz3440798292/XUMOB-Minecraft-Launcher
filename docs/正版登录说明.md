# 微软正版登录

点击右上角账户或首页启动面板的“修改”，选择“微软正版”。“使用 Windows 账户登录”通过 MSAL 调用 Windows Web Account Manager（WAM）系统账户窗口；如果该方式不可用，可改用设备代码登录，在浏览器中完成授权。完成后，启动器会读取当前 Microsoft 账户拥有的 Minecraft Java 版角色。

游戏使用该角色的名称、UUID 和授权信息。登录过期时会尝试刷新；缺少游戏许可、角色资料无效或授权被拒绝时，会提示重新登录，不会静默切换到离线账户。

## 微软应用配置

官方发行版会在构建时注入应用 Client ID，玩家可以直接登录。公开源码不包含维护者的 Client ID。自行构建时，可设置 `XUMOB_BUILD_MICROSOFT_CLIENT_ID`；也可通过 `XUMOB_MICROSOFT_CLIENT_ID` 为本机启动器配置。

应用需支持个人 Microsoft 账户、启用公共客户端流程，并获准访问 Minecraft 服务。使用 WAM 时，还要在 Azure 应用注册的“移动和桌面应用程序”平台中登记 `ms-appx-web://Microsoft.AAD.BrokerPlugin/{Client ID}` 重定向 URI。设备授权成功只表示微软登录可用，不代表 Minecraft 服务已批准该应用。无需 Client Secret。

Client ID 是公共客户端标识，授权请求仍需发送它。源码不公开或界面不显示该值，可以减少普通用户看到它的机会，但无法阻止从程序或网络请求中提取。

## 账户和数据

启动器保留离线账户。切换账户模式不会删除另一种账户的保存状态；在账户窗口点“退出登录”会清除本启动器保存的正版凭据，并切回离线模式。游戏运行或准备过程中不能更换账户。

数据默认保存在 `%LOCALAPPDATA%\XUMOB Minecraft Launcher\data`。账户类型及角色资料写入 `account.json`。设备代码登录的刷新令牌和 Minecraft 凭据使用当前 Windows 用户的 DPAPI 加密，写入 `account-session.bin`；WAM 登录的刷新令牌由 Windows Broker 管理，启动器只保存加密的账户引用及 Minecraft 会话。其他 Windows 用户或电脑无法解密，迁移后需重新登录。

密码只输入微软页面。访问令牌不返回给界面，普通日志会隐藏令牌。启动 Minecraft 时，令牌按游戏启动协议传给 Java 进程；请勿分享账户数据目录。

## 登录被拒绝

Minecraft 接口返回 HTTP 403 本身不能说明具体原因。若账户窗口明确显示 `Invalid app registration`，请应用所有者核对 Client ID 的注册信息和 Minecraft 服务许可，并通过 [Minecraft 应用审核入口](https://aka.ms/mce-reviewappid) 查询或申请权限。

其他 403 响应会显示为未明确分类。可以复制诊断文字继续排查；其中不包含原始响应、密码、登录代码或令牌。更多说明见[403 排查指南](Minecraft登录403排查说明.md)。

认证步骤：Microsoft 账户授权（WAM Broker 或[设备代码](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)）→ Xbox Live → XSTS → Minecraft 服务和 Java 版角色检查。WAM 由 [MSAL.NET Broker](https://learn.microsoft.com/en-us/entra/msal/dotnet/acquiring-tokens/desktop-mobile/wam) 调用；启动器构建时会生成自包含的登录组件，玩家不需要另装 .NET。
